# Turbofan Predictive Maintenance

Anomaly detection, remaining-useful-life (RUL) prediction and threshold-based maintenance alerts on NASA's C-MAPSS turbofan engine data, evaluated against the engines' actual failures.

The question this project answers: if these alerts were running on a fleet, **how many failures would they catch, how many alerts would be false, and how much warning would maintenance get?**

Full write-up with charts: [`report/index.html`](report/index.html) (open it in a browser).

## Results

Scored on the 707 NASA test engines, which no model or threshold was tuned on.

| Tier | Fires when | Failures caught | False alerts | Median warning |
|---|---|---|---|---|
| Watch | anomaly score above healthy threshold | 264 of 297 (29 late, 4 missed) | 25 of 318 fired | 84 cycles |
| **Plan maintenance** | predicted RUL ≤ T (T = 30–42, set per dataset) | **173 of 173** | **3 of 176 fired** | **32 cycles** |
| Urgent | predicted RUL ≤ 20 | 100 of 100 | 2 of 102 fired | 17 cycles |

Eight in ten Plan alerts leave between 23 and 43 cycles to schedule the shop visit. RUL test RMSE at the last observed cycle is 11–13 cycles on all four datasets (RUL capped at 125, the standard convention).

| FD002 | 6 | 1 | 12.2 | 716 |

## How an alert is judged

Each engine gets one decision per tier: the first time that alert fires. It is compared with the engine's real failure cycle.

| Tier | Window (cycles left) | Minimum lead | Persistence |
|---|---|---|---|
| Watch | ≤ 150 | ≥ 30 | 5 cycles in a row |
| Plan | ≤ 60 | ≥ 10 | 3 cycles in a row |
| Urgent | ≤ 30 | ≥ 3 | 3 cycles in a row |

- **Caught**: fired inside the window with at least the minimum lead time.
- **Late**: fired with less than the minimum lead time.
- **Missed**: no alert before failure.
- **False**: fired before the window opened, which would pull an engine with life to spare.

NASA's test trajectories stop before failure, so two more outcomes exist there: **quiet, correct** (never near failure, no alert) and **too soon to tell** (inside the window when the data ends, no alert yet). The second group is not counted as caught or missed.

## Method

1. **Operating regimes.** FD002 and FD004 fly six regimes. Each cycle is assigned to a regime by clustering the operating settings, and sensors are standardized within each regime against healthy early-life cycles.
2. **Sensor selection.** Keep sensors whose mean absolute shift near failure is at least 1.5 healthy standard deviations. Absolute shift matters because in FD003/FD004 the two fault modes push some sensors in opposite directions.
3. **Anomaly score.** Each engine is compared with its own first 20 cycles, which removes unit-to-unit differences in initial wear. The score is the Mahalanobis distance of that deviation under healthy-state noise, smoothed with an EWMA. Threshold: 99.5th percentile on early-life training cycles.
4. **RUL model.** `HistGradientBoostingRegressor` on 49 past-only features: normalized sensors, 10- and 30-cycle rolling means, 20-cycle slopes, the anomaly score and its trend, and cycle count.
5. **Threshold selection.** The Plan threshold is swept on out-of-fold predictions and scored as 10 × (late + missed) + 1 × false. The middle of the lowest-cost range is used.
6. **Validation.** Five-fold cross-validation grouped by engine on the 709 run-to-failure training engines, with all preprocessing refit inside each fold. The test set is scored once.

Leakage checks: no label-derived column reaches the model, and removing an engine's future cycles leaves its earlier predictions unchanged.

## Run it

```bash
pip install -r requirements.txt
bash get_data.sh          # downloads C-MAPSS FD001–FD004 into data/
python pipeline.py        # ~2 minutes; writes results/
python build_report.py    # rebuilds report/index.html
```

`python pipeline.py FD001` runs a single dataset.

## Outputs

| File | Contents |
|---|---|
| `results/results.json` | All metrics per dataset, split and tier |
| `results/alert_outcomes.csv` | Outcome and lead time for every engine × tier × split |
| `results/plan_threshold_sweep.csv` | Plan-threshold sweep on cross-validated predictions |
| `results/fleet_alert_snapshot.csv` | Alert status of each test engine at its last observed cycle |

Per-cycle predictions (`results/*.csv.gz`) are regenerated by the pipeline and not committed.

## Limits

- The windows and the 10:1 cost ratio are assumptions. A real fleet would set them from shop lead times and removal costs.
- Watch fires late on 12–32% of engines in FD002–FD004, where regime noise and the second fault mode raise the healthy threshold. Plan is unaffected.
- C-MAPSS is simulated: every engine degrades gradually, with no sudden failures or sensor dropouts.

## Data
